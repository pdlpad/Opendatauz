# Opendatauz — правила для работы в репозитории

Полное задание — в `SPEC.md`. Работать по этапам из раздела 7. После этапа 1 остановиться и показать отчёт инвентаризации.

## Данные
- Только опубликованное СИАТ (siat.stat.uz). Никаких интерполяций, оценок, заполнения пропусков, округлений.
- Пропуск = нет строки в CSV, `null` в JSON сайта, «нет данных» на экране. Никогда не 0. `0.0` из источника — это значение, а не пропуск.
- Ключ территории — код СОАТО из `klass_id`. Id СИАТ — только вспомогательное поле.
- Не досчитывать республику из регионов и регион из районов.
- Производный ряд — только при явном «нарастающим итогом» в note/methodology, отдельным файлом `*.derived.csv` и с пометкой на экране.
- Названия берутся из `/table/` (4 языка), не из `klassifikator` дампа. Метаданные — из `/metadata/`.
- ФИО, телефоны, e-mail сотрудников и поле `user` указателя дампа не сохранять нигде.
- Показатели, пропавшие из каталога, не удалять — проставить `removed_at`.
- Неизвестный формат периода или код территории — ошибка в отчёт, не догадка.

## API
- Каталог: `GET /api/sdmx/?lang=ru`.
- Дамп: `GET /api/sdmx/{id}/table/download/?download_format=json`, затем URL из поля `file_2`.
- Не больше 2 запросов в секунду, ретраи с backoff, `User-Agent: Opendatauz-sync (+https://github.com/pdlpad/Opendatauz)`.

## Экран
- У каждой цифры видны единица, период, дата обновления СИАТ и ссылка на источник.
- В подвале каждой страницы: «Неофициальное зеркало. Источник — Национальный комитет по статистике Республики Узбекистан».

## Код
- Python 3.12 в `tools/`.
- React + Vite + TypeScript в `site/`, маршрутизация через hash, base `/Opendatauz/`.
- Визуальный язык — как в `pdlpad/SOATO`, файл `tools/map_template.html`, ветка `claude/tender-einstein-1kly0y`.
- Коммиты по шагам. CI должен быть зелёным до мержа.
