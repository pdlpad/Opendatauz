# OchiqStat — открытое зеркало статистики Нацкомстата с привязкой к СОАТО

Задание для Claude Code. Репозиторий: `pdlpad/OchiqStat`, сайт: `https://pdlpad.github.io/OchiqStat/`. Если имя репо другое, поменять только base path сайта (`/OchiqStat/`).

Проект-брат `pdlpad/SOATO`: там справочник махаллей по СОАТО. Здесь все 3 237 показателей портала СИАТ (siat.stat.uz) с ключом СОАТО:
- данные в git;
- еженедельное автообновление через GitHub Actions;
- статический сайт на GitHub Pages: каталог, карта, график, таблица, карточка территории.

Проект неофициальный. Источник каждой цифры — Национальный комитет по статистике (siat.stat.uz), это указывается на каждом экране.

### Полный дамп показателя (главный способ загрузки)
1. `GET /api/sdmx/{id}/table/download/?download_format=json` возвращает указатель. В нём поле `file_2` — URL вида `https://siat.stat.uz/media/uploads/sdmx/import/v2/<code>_<hash>.json`. В указателе есть поле `user` (e-mail загрузчика): **не сохранять**.
2. `GET <file_2>` возвращает дамп: `{success, total_counts, description, data: [...]}`.
   - Каждая строка `data`: `klass_id`, `klassifikator`, `values: [{year, value}]`, `publish_date`, `change_date`, `point_code`, `point_name`, `unit`, `periodicity` и метаданные.
   - **В дампе сразу все строки, включая районы.** Отдельно по регионам ходить не нужно.

`total_counts` в проверенных дампах:

| Показатель | total_counts | Разрез |
|---|---|---|
| 544 ВВП годовой | 1 | только республика |
| 2189, 2950 | 15 | республика + 14 регионов |
| 246 население, 2415, 1575 | 221 | республика + 14 регионов + 206 районов/городов |
| 227 число умерших (ж) | 222 | то же + исторический `1735411` Тахиатош ш. |
| 562, 604, 4499 | 29 | ОКЭД (`klass_id` = `B, C, D, E`, `B`, `C`…) |
| 1323 | 116 | ТН ВЭД (`6` = сводный, `01.0`, `01.1`…) |
| 1170 экспорт по странам | 233 | страны, числовой код (`192` Куба) |
| 4725 индекс цен жилья | 13 | собственная иерархия кодов `1`, `1.1`, `1.1.1` |

- **`klass_id` у территорий = код СОАТО.** `1700` — республика, 4 знака — регион, 7 знаков — район или город.
- У показателя 246 все 206 районов и городов несут код, дублей нет. Территориальный справочник строится из самих данных.
- Сопоставление «id СИАТ → СОАТО», которое делали вручную в сентябре, больше не нужно. Достаточно сверки.
- Форматы периода в дампах: `2025`, `2026-Q2`, `2026-M08`. Неизвестный формат — падать с ошибкой, не угадывать.
- `values` бывают `0.0`, например у 1170. Это опубликованное значение, не пропуск.
- Названия в дампе (`klassifikator`) есть только на узбекской кириллице и с опечатками: `Aндижон` с латинской `A`. **Названия брать не из дампа**, а из `table` (см. ниже).
- Метаданные внутри дампа называются по-разному у разных показателей: `department` / `mas’ul_boshqarma_nomi`, `note` / `izoh-1`, `email` / `elektron_pochtasi`. Нормализованные метаданные брать из `/metadata/`.
- Вес дампа 246 — 788 КБ: 221 строка × 17 лет, но методология повторена в каждой строке. В нормализованном виде это 3 757 значений.

## 2. Ловушки в данных — правила обработки

1. **Нарастающий итог.** Часть квартальных и месячных рядов идёт нарастающим итогом с начала года.
   - Хранить как опубликовано.
   - Значения за период — отдельный производный ряд `is_derived=true`. Строится только если в `note` или `methodology` прямо сказано «нарастающим итогом» / «o'sib boruvchi yakunda».
   - Монотонность внутри года — только флаг `maybe_cumulative` для ручной проверки, без автопересчёта.
2. **Регионы ≠ республика.** Сумма регионов по ВРП не равна республике. Никогда не досчитывать республику из регионов и регион из районов. Показывать опубликованное.
3. **Цены и единицы.** Объёмы в текущих ценах, темпы — в сопоставимых. Единицы разные: млрд сум, млн сум, тыс. чел., `в процентах`, `Бирлик`. Единица всегда из metadata. Значения без пересчёта и округления.
4. **Устаревшие показатели.** У 259 статус `Muddati o'tgan`, у 122 — `Yangilanmaydigan`. Показывать бейдж статуса и дату последнего обновления.
5. **Изменения территорий.** В примечании к 246 сказано, что Бузатовский район образован в 2020 году, а город Тахиаташ исключён в 2013-м. При этом `1735411` Тахиатош ш. есть в дампе 227. Справочник территорий хранит статус `active` / `historic`. Неизвестный код — не выкидывать, а добавить с `status=unknown` и в отчёт.
6. **Пропуск ≠ ноль.** Нет значения — нет строки в CSV, `null` в JSON сайта, «нет данных» на экране.
7. **Персональные данные.** ФИО, телефоны, e-mail сотрудников и поле `user` из указателя дампа в репозиторий не попадают. Это проверяет тест.

## 3. Структура репозитория

```
data/
  catalog.json                 # дерево разделов + все показатели (см. схему ниже)
  territories.csv              # справочник СОАТО: soato, level, parent_soato, siat_id, name_uz, name_ru, name_en, name_uzc, map_code, status, first_period, last_period
  classifiers/
    okved.csv  tnved.csv  countries.csv  other/<indicator_code>.csv   # code, parent_code, name_uz, name_ru, name_en, name_uzc
  indicators/<раздел.подраздел>/<code>.csv        # long: key,period,value
  indicators/<раздел.подраздел>/<code>.json       # метаданные показателя
  indicators/<раздел.подраздел>/<code>.derived.csv  # только для явного нарастающего итога
  geo/regions.topojson  geo/districts.topojson
  manifest.json                # id → updated_xlsx, sha256 файлов, fetched_at
  sync_log/<YYYY-MM-DD>.json   # что изменилось за прогон
tools/
  siat_client.py   siat_sync.py   build_site_data.py   validate.py   inventory.py
site/              # React + Vite + TypeScript
schema/            # JSON Schema для catalog, meta, territories
tests/
.github/workflows/  sync.yml  pages.yml  ci.yml
README.md  SOURCES.md  DATA_LICENSE.md (CC BY 4.0)  LICENSE (MIT)  CLAUDE.md
```

**Почему подпапки по `раздел.подраздел`** (`2.01/2.01.02.0001.csv`): GitHub показывает в папке не больше 1 000 файлов, а у нас 3 237 × 2–3 файла.

**Почему CSV long в git.** Изменение значения задним числом видно в диффе. История ревизий Нацкомстата бесплатно получается из `git log`. Это отдельная ценность проекта, сделать её видимой: страница «Что изменилось».

**`<code>.csv`**: колонки `key,period,value`, сортировка по `key`, `period`.
- `key` — СОАТО или код классификатора.
- `period` — как в источнике: `2025`, `2026-Q2`, `2026-M08`.
- `value` — число ровно как в JSON источника.

**`<code>.json`**: `id`, `code`, `names{uz,ru,en,uzc}`, `section_path`, `period_type`, `unit{...}`, `dimension`, `levels`, `status`, `updated_xlsx`, `last_import_date`, `publish_date`, `methodology`, `note`, `info_source`, `org_name`, `department`, `period_range`, `n_keys`, `n_values`, `flags`.
- `dimension` — одно из: `territory` / `okved` / `tnved` / `country` / `other`.
- `levels` — для территорий: `[country, region, district]`.
- `flags` — например `maybe_cumulative`, `cumulative_explicit`.

**`catalog.json`**: дерево разделов и по каждому показателю сжатая карточка: `id`, `code`, `names`, `period_type`, `dimension`, `levels`, `status`, `updated_xlsx`, `period_range`.

**Классификация разреза** (`dimension`):
- `territory` — все `klass_id` подходят под `^17\d{2}(\d{3})?$` или `1700`;
- иначе по тексту `classifiers` из metadata и шаблону кодов:
  - ОКЭД — буквы секций;
  - ТН ВЭД — `\d{2}\.\d`;
  - страны — 1–3 цифры при `classifiers` = «Классификатор стран мира»;
- всё, что не распозналось, — `other`. Список `other` попадает в отчёт этапа 1, вручную ничего не угадывать.

## 4. Синхронизация (`tools/siat_sync.py`)

Клиент (`siat_client.py`):
- ≤ 2 запроса/с;
- таймаут 60 с;
- 4 попытки с экспоненциальным backoff;
- `User-Agent: OchiqStat-sync (+https://github.com/pdlpad/OchiqStat)`;
- кэш сырых ответов в `.cache/` (в `.gitignore`).

Алгоритм прогона:
1. Скачать каталог (1 запрос), развернуть листья, сравнить `updated_xlsx` с `manifest.json`. Получаются три списка:
   - новые;
   - изменившиеся;
   - пропавшие — их не удалять, а проставить `removed_at`.
2. Для новых и изменившихся:
   - указатель → дамп;
   - `/metadata/`;
   - `/table/` — только если `dimension ≠ territory` или изменился набор ключей.
3. Нормализация:
   - периоды по формату;
   - значения как есть;
   - строки отсортированы;
   - запись CSV и JSON атомарно (временный файл, затем rename).
4. Сверка дампа с `/table/`: для территориальных показателей значения республики и 14 регионов за последние 3 периода должны совпасть.
   - При расхождении показатель не коммитится.
   - Он попадает в `sync_log` с причиной.
5. Справочник территорий:
   - основа — 15 + 206 кодов из показателя 246 с названиями на 4 языках;
   - коды из дампов, которых нет в основе, добавляются со статусом `historic`, если ряд обрывается раньше текущего года, иначе `unknown`;
   - название для таких кодов берётся из `klassifikator`, остальные языки пустые.
6. Выход: `sync_log/<дата>.json` (новые, обновлённые, удалённые, ошибки, новые периоды по показателям) и код возврата ≠ 0, если ошибок больше 2 % от обработанных.

Объём:
- первый полный прогон — 2–3 запроса на показатель, то есть 6,5–9,7 тыс. запросов, при 2 запросах/с это примерно 1–1,5 часа;
- недельный — порядка 240 показателей, примерно 720 запросов, около 6 минут.

## 5. GitHub Actions

- **`sync.yml`**:
  - запуск: `schedule: '0 1 * * 1'` (понедельник 06:00 Ташкент) и `workflow_dispatch` с входом `full: true|false`;
  - `concurrency: sync`, `timeout-minutes: 300`;
  - шаги: Python 3.12 → `siat_sync.py` → `validate.py` → коммит от `github-actions[bot]` с сообщением `sync YYYY-MM-DD: обновлено N, новых M, новых периодов K`;
  - если ошибок больше порога — открыть issue с выдержкой из `sync_log`.
- **`pages.yml`**: на push в `main` по путям `data/**` и `site/**` → `build_site_data.py` → `npm ci && npm run build` → `actions/upload-pages-artifact` → `actions/deploy-pages`. В настройках репо: Pages → Source = GitHub Actions.
- **`ci.yml`**: на PR — `pytest` и `npm run typecheck && npm run build`.
- **Первым делом** проверить, отвечает ли siat.stat.uz из GitHub-раннера: отдельный `workflow_dispatch`-job с `curl` на каталог и 3 дампа. Если раннер получает таймаут или 403, нужен self-hosted runner на ВМ в Узбекистане с меткой `uz`, а `sync.yml` переводится на `runs-on: [self-hosted, uz]`.

Лимиты GitHub Pages (docs.github.com):
- репозиторий — рекомендовано до 1 ГБ;
- опубликованный сайт — до 1 ГБ;
- деплой — до 10 минут;
- трафик — мягкий лимит 100 ГБ/мес;
- лимит 10 сборок/час на сборку через собственный Actions-workflow не распространяется;
- файл в git — до 100 МБ.

Контроль в `validate.py`:
- `data/` больше 500 МБ или сборка сайта больше 700 МБ — предупреждение в `sync_log`;
- любой файл больше 50 МБ — ошибка.

## 6. Сайт (`site/`)

Стек: React + Vite + TypeScript, ECharts (модульный импорт `echarts/core`), d3-geo для SVG-карт, MiniSearch для поиска. Без бэкенда.
- Маршрутизация через hash, чтобы на GitHub Pages не было 404: `#/`, `#/i/<code>`, `#/t/<soato>`, `#/changes`.
- Состояние в URL, чтобы любую ссылку можно было переслать.
- `base: '/OchiqStat/'`.

Данные для сайта собирает `build_site_data.py` в `site/public/data/` при сборке. В git они не коммитятся.
- `catalog.min.json` — для поиска и дерева.
- `i/<code>.json` — `{meta, periods[], series: {key: [values по periods, null = нет]}}`.
- `t/<soato>.json` — все показатели, где есть эта территория: последний период, значение, единица, ряд для спарклайна.
- `geo/regions.json`, `geo/districts.json` — TopoJSON, упрощённый, суммарно меньше 1 МБ.

Экраны:
1. **Главная / каталог.**
   - KPI в стиле SOATO: показателей 3 237; из них с регионами N, с районами M (числа из `catalog.json`, не захардкожены); дата последней синхронизации; сколько обновилось за неделю.
   - Дерево 5 разделов.
   - Поиск по названиям на 4 языках и по коду, кириллица и латиница.
   - Фильтры: периодичность, разрез (республика / регионы / районы / ОКЭД / ТН ВЭД / страны / другое), статус, ведомство.
2. **Показатель `#/i/<code>`.**
   - Шапка: название, код, единица, периодичность, бейдж статуса, «обновлено СИАТ: дата», ссылка на siat.stat.uz.
   - Карта регионов или районов за выбранный период: хороплет с квантильной легендой как в SOATO, серым «нет данных».
   - Переключатель периода.
   - График ряда: республика и выбранные территории, или элементы классификатора.
   - Таблица ключ × период.
   - Методология и примечание.
   - Скачать CSV и JSON этого показателя.
   - Для нетерриториальных показателей карты нет: дерево классификатора и топ-N за период.
   - Производный ряд показывать отдельной вкладкой с пометкой «рассчитано из нарастающего итога».
3. **Территория `#/t/<soato>`** — главное отличие от портала.
   - Карточка региона или района: все показатели, где он есть, с последним значением и спарклайном, сгруппированные по разделам.
   - Поиск внутри карточки.
   - Переход к соседям и родителю.
4. **Что изменилось `#/changes`** — из `sync_log`: какие показатели обновились, где добавились периоды, где пересмотрены прошлые значения (по диффу CSV).

## 7. Этапы и критерии приёмки

Каждый этап — отдельный PR с понятными коммитами. Следующий этап не начинать, пока не выполнены критерии текущего.

**Этап 0. Каркас.**
- Структура из раздела 3, лицензии, `CLAUDE.md`, `SOURCES.md`, схемы, `ci.yml`, пустой сайт с base path.
- Готово, когда CI зелёный.

**Этап 1. Инвентаризация** (`tools/inventory.py`). Полный проход по 3 237 показателям: указатель + дамп + metadata. Результат — `inventory.md` и `inventory.csv` со следующим:
- распределение по `dimension` и `levels`;
- форматы периодов;
- все единицы;
- `total_counts`;
- коды, не найденные в справочнике территорий;
- показатели с явным «нарастающим итогом»;
- суммарное число значений и оценка размера `data/`;
- ошибки с причинами;
- результат проверки маршрута `/reports-filed/:menu/table`.

Готово, когда 3 237 из 3 237 показателей обработаны или каждая ошибка описана. После этапа — стоп и показать отчёт.

**Этап 2. Нормализация и справочники.**
- `territories.csv`, `classifiers/`, `indicators/`, `manifest.json`.
